01 / MEMOP · MOBILE APPLICATION

Built for the field.
Ready without a signal.

An Android-first records app that organizes people, vehicles, encounters, and investigations. Local records remain accessible offline, with encrypted team collaboration available in a separate context.

FlutterDartRiverpodDrift / SQLCipher
Explore MemOp ↗Private product source

Local-first workflows

Encrypted on-device storage, structured records, photos, maps, and backup and restore workflows.

Explicit data contexts

Local usage and team collaboration have separate data contexts, with account capabilities controlling access.

From app to release

Biometric authentication, Google Drive integration, RevenueCat subscriptions, and Android release automation.

Engineering details

Riverpod manages application state, go_router handles navigation, and Drift sits over an encrypted SQLCipher database. Team mode integrates with REST and Socket.IO; sensitive team content is encrypted on the client before synchronization.

02 / MEMOP · BACKEND & INFRASTRUCTURE

The system
behind the app.

A TypeScript backend for identity, team authorization, subscriptions, and encrypted record synchronization, with separate runtimes for requests, durable work, and scheduled jobs.

TypeScript / Node.jsPostgreSQLRedisCloud Run
Visit product ↗Private product source

Clear service boundaries

Express API, private background worker, and isolated migration, maintenance, and backup jobs.

Encrypted collaboration

PostgreSQL stores canonical state. Redis coordinates real-time delivery, while R2 stores encrypted attachments.

Deployment and recovery

Cloud Run is the primary deployment profile, with Fly.io and self-hosted fallbacks documented alongside release and recovery procedures.

Engineering details

Prisma models relational data, while SQL migrations maintain database invariants. Cloud Tasks invokes the private worker; GitHub Actions builds role-specific images and applies migrations before deployment. The repository also includes Terraform, k6 tooling, and monitoring configuration.

Python key-handling demo

A runnable showcase follows the client-side key flow from the password-derived key to the user master key, private key, and wrapped team keys. It uses an in-memory mock server for learning.
